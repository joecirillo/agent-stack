## Unattended Sessions
These sessions run without me watching, so asking a question stalls the work.
- Proceed on reasonable defaults instead of asking. Record each assumption in the PR description so I can check it in review.
- For anything non-trivial, put the plan in the PR description rather than waiting for approval before writing code.
- When work is out of scope, or a review suggestion is deferred rather than fixed, file a GitHub issue for it (check for duplicates first) and link the issues under "Follow-ups" in the PR description.
- Explain *what changed and why* in the PR description, not a line-by-line narration.
